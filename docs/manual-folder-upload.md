# Set test 폴더 및 여러 파일 업로드

## 화면/사용법

기존 이미지 선택, CSV 선택, 업로드 버튼의 한 줄 배치를 유지한다.
각 '파일 선택' 버튼을 누르면 작은 메뉴에서 여러 파일 또는 폴더 선택을 고를 수 있다.
폴더 선택은 Chrome/Edge의 webkitdirectory 기능을 사용하며 하위 폴더를 포함한다.
이미지 폴더에서는 PNG/JPEG/WebP, CSV 폴더에서는 CSV만 사용하고 다른 확장자는 제외한다.
선택을 취소하면 기존 선택을 유지한다.
이미지 1개 + CSV 1개일 때는 이전처럼 바로 업로드한다.

여러 파일이면 업로드 버튼을 누를 때 연결 확인 목록을 표시한다.
확장자를 제외한 파일명이 같은 경우에만 자동 매칭한다.
파일명이 다르거나 같은 이름의 CSV가 하위 폴더에 중복되면 직접 CSV를 지정해야 한다.
모든 이미지에 CSV가 지정되기 전에는 확인 업로드 버튼이 비활성화된다.
이미지 경로/파일명의 자연 정렬 순서(2 다음 10)로 재생한다.
동일 센서 CSV가 여러 이미지에 해당하는 경우 같은 CSV를 여러 번 지정할 수 있다.
단순히 이미지와 CSV의 정렬 순서가 같다고 연결하거나, 근거 없이 시간으로 추측하지 않는다.

업로드 완료된 다량 입력은 서버에 별도 재생 목록으로 저장한다.
현재 CSV 재생이 끝나면 다음 이미지/CSV로 넘어가고 마지막 데이터가 끝나면 목록 처음으로 돌아간다.
다음 CSV를 불러오는 동안 재생 시계는 기다리므로 로딩 중 데이터 재생 구간을 건너뛰지 않는다.
파일을 실제로 불러오는 브라우저의 지연은 발생할 수 있다. 즉시 전환을 보장하지 않는다.
새로고침하면 최신 저장 목록을 불러와 처음부터 재생한다.
여러 저장 기록이 있을 때만 저장된 입력 선택 목록이 나타난다.
Set 1~8 자동 모니터링과 DB 알림/세션 reset은 변경하지 않는다.
Set test 이름 매핑/탭 파일, 로고 복귀 동작 및 사용자가 지운 용량 안내는 변경하지 않는다.

## 저장/실패

이미지 한 파일 8MB, CSV 한 파일 20MB, 재생 목록 이미지 최대 1,000개.
원본 업로드 API를 한 쌍씩 호출하므로 서버 요청 한 건에 폴더 전체를 넣지 않는다.
매칭과 이미지 디코딩/CSV 내용은 업로드 시작 전 모두 검증한다.
저장 도중 통신/공간 부족으로 실패하면 이미 저장한 쌍은 유지하고 그 수를 안내한다.
전체 목록은 모든 쌍 저장 후 생성한다. 실패 전 저장 기록은 저장된 입력에서 확인할 수 있다.
다시 전체 업로드하면 새 기록이 생긴다. 실패한 요청을 자동 재시도하여 중복 생성하지 않는다.
업로드가 완료될 때까지 탭을 닫거나 Set을 이동하지 않는 것이 좋다. 이동하면 다음 쌍 업로드는 중단하며 진행 중인 요청 한 건은 서버에 저장될 수 있다.
기본 저장 총 용량은 기존 512MB이다. 큰 폴더를 넣을 때 필요하면 백엔드 환경변수 MANUAL_INPUT_QUOTA_MB로 용량을 조정한다.
예: PowerShell에서 백엔드 시작 전 `$env:MANUAL_INPUT_QUOTA_MB = "2048"`.
운영은 기존처럼 영구 볼륨 및 Nginx 업로드 크기 설정이 필요하다.

새 API:
- GET /api/manual-inputs/playlists: 저장 목록과 연결된 입력 조회
- POST /api/manual-inputs/playlists: item_ids(순서 있는 UUID 목록), name으로 목록 저장
기존 업로드/이미지/센서/단건 조회 API와 이전 저장 기록은 유지한다.
추론은 이번 패치에 포함하지 않는다. 예측 마모량/유형은 대기 상태이며 추론 경고·위험 알림도 아직 생성되지 않는다.

## 적용 후 검증

1. 백엔드 재시작(리셋 호출 불필요), 프런트 새로고침.
2. 기존 한 쌍 업로드와 재생 확인.
3. 이미지와 CSV 폴더 각각 선택, 무관한 파일 제외 및 개수 확인.
4. 자동 매칭/중복 이름/누락 CSV의 연결 확인 화면 검증.
5. 두 쌍 이상 업로드, 순차 재생, 마지막에서 처음으로 반복, 새로고침 후 복원 확인.
6. 기존 Set으로 이동했을 때 입력 폼이 없고 기존 그래프가 정상인지 확인.

자동 검증: 프런트 31개 테스트 및 Vite build, 백엔드 64개 테스트 통과(실제 MySQL opt-in 1개 생략).
한국어/영어 SSR에서 두 선택 버튼/두 폴더 input 및 기존 Set 입력 폼 없음도 확인했다.
실제 Windows 폴더 선택 대화상자 및 사용자 브라우저에서의 최종 조작은 로컬 적용 후 확인이 필요하다.
