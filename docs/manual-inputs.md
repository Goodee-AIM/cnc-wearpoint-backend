# 사용자 입력 탭

## 동작

- 기존 UI Set 1~8(원본 번호 4~11), 자동 모니터링, 알림 이력, reset API는 그대로 유지한다.
- 대시보드의 `이미지·센서 업로드` 버튼 또는 `사용자 입력` 탭으로 진입한다.
- 이미지와 센서 CSV 한 쌍을 선택하고 `업로드하고 재생`을 누른다.
- CSV는 헤더 없는 숫자 5열과 시간 1열이며, UTF-8 형식이다. 시간순 두 행 이상이고 전체 기간은 0보다 커야 한다.
- 파일 내용은 기존 그래프 변환 함수로 최근 5초 구간을 표시한다. 일시정지와 처음부터 재생을 제공한다.
- 업로드 목록은 서버에 저장한다. 새로고침하면 최신 입력을 다시 조회하며 사용자 입력 재생은 처음부터 시작한다.
- 사용자 입력 탭 선택은 브라우저 탭의 sessionStorage로 유지한다. 기존 Set 버튼으로 돌아갈 수 있다.
- 기존 Set의 useDashboard는 계속 마운트된 상태이며 백엔드 자동 모니터링도 계속 동작한다.
- 이 단계에서는 모델 추론, 사용자 입력 알림 생성, DB 스키마 변경을 구현하지 않았다. 마모량·유형·판정은 예측 대기 상태다. 임의 예측값이나 정답 라벨을 만들지 않는다.

## 저장

기본 저장 위치는 백엔드 실행 폴더의 `manual-inputs/`이다. `.gitignore`에 포함된다.
원본 파일 두 개와 metadata.json을 별도 UUID 폴더에 저장한다. monitoring reset과 독립적이다.
기본 총 파일 용량 제한은 512MB(`MANUAL_INPUT_QUOTA_MB`로 변경). 파일 자동 삭제는 없다.
이미지는 PNG/JPEG/WebP, 8MB까지, CSV는 20MB까지 허용한다.
브라우저에서 이미지 디코딩을 확인하고 서버에서는 형식 시그니처와 CSV 전체를 검사한다.
파일명은 표시용으로만 저장하며, 실제 저장 경로는 서버가 만든 UUID와 고정 파일명을 사용한다.
아직 사용자별 계정/권한 구분은 없고 목록은 서비스 사용자 사이에 공유된다.

## API

| Method | URL | 내용 |
|---|---|---|
| POST | /api/manual-inputs | JSON으로 image_name, sensor_name, image_base64, sensor_base64를 전달 |
| GET | /api/manual-inputs | 저장된 입력 목록 |
| GET | /api/manual-inputs/{id} | 입력 메타데이터 |
| GET | /api/manual-inputs/{id}/image | 저장 이미지 |
| GET | /api/manual-inputs/{id}/sensor | 원본 CSV |

별도 multipart 라이브러리 없이 JSON으로 전송한다. Base64로 인해 요청 크기는 원본보다 커진다.

## 로컬 적용 후

1. 실행 중인 백엔드를 Ctrl+C로 종료하고 기존 환경 변수와 실행 방법으로 재시작한다. reset을 호출하지 않는다.
2. 프런트는 `npm.cmd run build`, `node --test tests/*.test.js`로 확인한다. 기존 Vite가 켜져 있으면 재사용한다.
3. 업로드 → 이미지/그래프 → 일시정지 → 처음부터 재생 → 새로고침 → 기록 조회 → 기존 Set 복귀를 확인한다.
4. 다른 브라우저/백엔드 재시작 후에도 업로드 파일이 조회되는지 확인한다.
5. 잘못된 CSV는 저장되지 않아야 한다. 기존 자동 모니터링 세션/알림이 초기화되지 않아야 한다.

## 운영 배포 시 필수 설정

이 패치는 운영에 자동 배포하지 않는다.

- `MANUAL_INPUT_ROOT`를 별도 쓰기 가능한 영구 볼륨에 지정해야 컨테이너 재생성 후 파일이 유지된다.
- 제공된 `infra/compose/compose.manual-inputs.yaml`은 실제 Compose 파일과 합쳐 사용하는 예시다. 기존 backend 서비스 이름이 다르면 맞춰야 한다. 기존 MATWI 읽기 전용 볼륨은 유지한다.
- 예: `docker compose -f <실제 Compose 파일> -f infra/compose/compose.manual-inputs.yaml up -d backend` (경로는 운영 환경에 맞춘다.)
- 프런트 컨테이너 및 외부 VM Nginx 모두 업로드를 통과하도록 `client_max_body_size 40m;`를 설정해야 한다. 제공된 저장소 Nginx 예시에는 반영했다. 실제 운영 VM 설정은 별도로 확인해야 한다.
- 기존과 같은 태그 배포를 하더라도 위 볼륨과 Nginx 설정이 없는 상태로 배포하면 저장 유지/대용량 업로드가 보장되지 않는다.
- 모델 연결 시 추론 결과 저장과 조회, 처리 상태 폴링 및 사용자 입력 알림을 추가한다. 현재 metadata의 null 예측 필드만 채우는 것으로 추론 시스템이 구현되는 것은 아니다.

## 검증 범위

기존 프런트 Node 테스트 28개, 신규 업로드 API unittest 2개, Vite 프로덕션 빌드를 확인했다.
API 테스트는 임시 폴더와 독립 앱에서 수행하며 기존 DB에 접속하지 않는다.
브라우저 실행은 작업 환경의 프로세스/소켓 제한으로 실패해 실제 사용자 브라우저의 최종 UI 확인이 필요하다.
